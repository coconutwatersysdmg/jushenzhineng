# 现场软件测试计划（坐标输出 / 不操作机械臂）

> 文档状态：初稿，可按现场实际情况增删改。  
> 适用软件：巨神智能 / 具身智能装载数字孪生（`jushenzhineng_v3`）  
> 运行模式：界面顶部选择 **「完全真实 / field」**  
> 测试原则：**流程编排与实验室一致**（感知 → 出坐标 → 对方确认/执行 → 回拍校验）；**我方现场不操纵机械臂**，只给出 WORLD / PLC 目标坐标。

---

## 1. 文档目的

本计划用于约定：

1. 现场联调时**测试怎么排、按什么顺序跑**；
2. **我方（软件侧）**与**甲方（装备 / PLC / 现场运维侧）**各自负责什么；
3. 甲方需要**提前准备、现场提供**哪些条件与资料；
4. 每一轮测完看什么结果、怎样算通过。

本计划**不是**全自动无人装车验收方案。当前现场测试阶段的目标是：

- 验证现场算法链路（雷达粗定位、相机角点、插孔识别、划格规划、放置点计算等）在真实车/货上可用；
- 验证软件能稳定输出**可核对、可下发**的坐标；
- 由甲方侧根据坐标完成机械臂/龙门架运动，或由甲方人员按坐标人工确认位姿后继续后续步骤。

---

## 2. 与实验室测试的关系（异同）

### 2.1 相同点（建议现场按此思路执行）

| 维度 | 实验室 | 现场（本计划） |
|------|--------|----------------|
| 总体节奏 | 设备检查 → 感知出坐标 → 确认 → 放置/校验 → 下一格 | 相同 |
| 坐标交互 | 弹窗展示 XYZ，可改后确认下发 | 相同（我方只给坐标，不直接“上手开臂”） |
| 首轮建图 | 雷达粗点 + 相机精定位 + 划格 | 相同业务意图（现场用 field 算法） |
| 循环装载 | 复用首轮板型，逐区验证 | 相同 |
| 失败处理 | 本步重试优先，不盲目跳过 | 相同 |

### 2.2 不同点（现场必须注意）

| 维度 | 实验室 | 现场 |
|------|--------|------|
| 运行模式 | `lab`（实验室雷达/相机算法） | `field`（现场 PointNet / corner 等） |
| 机械臂操作权 | 实验室可联 PLC 逐步确认下发 | **我方不操纵机械臂**；坐标给甲方/PLC 操作员执行 |
| 场景尺寸 | 实验室缩比/固定工位 | 真实车厢、真实托盘、真实龙门行程 |
| 安全责任 | 实验室安全规程 | 甲方现场安全规程、急停、禁区 |
| 标定参数 | 实验室外参包 | **必须使用现场已标定外参**（见第 5 节甲方提供项） |
| 插取动作 | 实验室可“只识别不下发插取” | 本阶段默认**只出插孔/到位坐标，不做由我方发起的物理插取**（若甲方要求试插取，单独开专项） |

> 一句话：现场测试 = **实验室那套“出坐标给人确认”的作业方式**，换到真实场地 + 现场算法；运动执行权在甲方。

## 3. 测试目标与非目标

### 3.1 本阶段目标（建议写入验收口径）

1. **设备连通**：PLC / Livox 雷达 / RealSense D435i 在现场网络下可被软件识别为已连接。
2. **感知正确性**：
   - 雷达能给出车板粗角点（或等效粗定位结果）；
   - 相机能识别托盘左右插孔并输出 WORLD 坐标；
   - 相机能完成车板角点识别并转换到 WORLD；
   - 首轮能完成板型判断与装载区域划格（如 A/B 列 × 排）。
3. **坐标可用性**：
   - 每一步关键坐标在界面/日志中可读、可截图、可导出；
   - 坐标系、单位（mm）、轴含义与甲方约定一致；
   - 甲方可按坐标驱动机械臂到位（或人工核对误差在约定阈值内）。
4. **闭环可重复**：至少完成「首轮建图 + 不少于 N 个区域/件货的循环验证」（N 由双方会前约定，建议 ≥ 3）。
5. **异常可恢复**：断连、识别失败、坐标异常时，有明确重试路径，不污染后续轮次数据。

### 3.2 本阶段非目标（可后续专项）

- 我方人员现场遥控/点动机械臂完成完整插取—放货无人闭环；
- 生产节拍、全车装满效率验收；
- 全天候、全车型、全货型泛化验收；
- 未标定完成前的精度考核（标定未完成则只做连通与流程演示）。

## 4. 角色与职责

### 4.1 我方（软件 / 算法联调）

- 携带并部署现场软件包（含 `runtime`、模型、配置模板）；
- 配置运行模式为 **field**，按甲方提供的 IP/外参填写配置；
- 操作上位机软件：逐步执行流程、查看结果、记录日志与截图；
- 在 PLC 坐标弹窗中**展示/核对/必要时微调坐标数值**，但不代替甲方操作机械臂安全权限；
- 输出测试记录、问题清单、坐标对照表；
- 现场问题判定：软件 bug / 算法阈值 / 标定 / 现场条件。

### 4.2 甲方（装备 / PLC / 现场）

- 提供测试场地、车辆（或等效车板工装）、托盘货物、供电与网络；
- 提供 PLC / 龙门架操作权限与持证操作人员；
- **根据软件给出的坐标执行机械臂运动**（或使用甲方自有示教/点动界面到位）；
- 负责现场安全：急停、围栏、人员站位、防撞；
- 提供/确认现场标定参数、零点、轴方向、软限位；
- 确认装载业务规则（列/排顺序、平板/高低板定义、放货高度约定等）。

### 4.3 建议联调指挥方式

- 每一段运动前：**软件喊坐标 → 双方口头确认 → 甲方执行 → 到位回报 → 软件继续下一步**；
- 任何涉及 Z 下降、插取、放货的动作，必须由甲方确认安全后执行；
- R 轴策略预先书面约定（常见：现场保持 R，不下发 R；以双方签字的约定为准）。

## 7. 测试阶段安排（建议日程）

> 可按 2～3 天压缩或拉长；以下为逻辑阶段，不一定严格按自然日。

### 阶段 A：进场前（T-7 ～ T-1）

1. 双方确认本计划与「只出坐标、不操纵机械臂」原则；
2. 甲方提交第 5 节清单（尤其 N1–N3、C1–C4）；
3. 我方预填配置，远程或邮件确认网段不冲突；
4. 约定测试车型、货型、轮次数 N、通过阈值；
5. 安全与责任边界书面确认。

### 阶段 B：进场首日 — 连通与静态核对（0.5～1 天）

1. 部署软件，安装缺失驱动；
2. 跑 **设备连接检查**（PLC / 雷达 / 相机）；
3. 只读 PLC 当前坐标，与甲方示教器/面板对照；
4. 雷达短采一帧、相机预览一帧，确认不是“假在线”；
5. 核对坐标系方向（在已知特征点上做一次静态对照，哪怕只用卷尺粗核）。

**阶段出口**：三设备为「已连接」；坐标轴方向双方无异议。

### 阶段 C：首轮建图验证（0.5～1 天）

按第 8 节「首轮流程」逐步执行：感知 → 出坐标 → 甲方到位 → 回拍/确认 → 划格。

**阶段出口**：车板 WORLD 四角（或约定角点数）双方认可；装载区域划分结果甲方认可。

### 阶段 D：循环区域验证（1 天）

按第 8 节「循环流程」完成 ≥ N 个区域/件：插孔坐标、目标区中心、放置相关坐标均可复现。

**阶段出口**：连续 N 次无阻断性软件故障；坐标误差在约定阈值内（或记录在案的已知偏差有解释）。

### 阶段 E：异常与收尾（0.5 天）

1. 模拟断网/拔相机/雷达失败，确认提示与重试；
2. 整理日志、截图、点云、坐标表；
3. 问题分级（P0/P1/P2）与后续整改项；
4. 双方签署《现场测试纪要》（可附本计划修订版）。

## 8. 详细测试流程（对齐实验室节奏）

说明：

- 下列步骤描述的是**现场测试作业流程**，业务节奏对齐实验室「检查 → 感知出坐标 → 确认 → 放置/校验 → 下一轮」。
- 软件内部 field 模式步骤编号仍对应完整装载链（1～12）；测试时**可以逐步执行**，但凡涉及机械臂位移，一律：**软件给坐标 → 甲方执行**。
- 若现场软件版本已支持「仅发布坐标、不自动写轴」，优先打开该策略；若仍弹出下发框，则由甲方确认是否允许写轴，我方不代替操作安全确认。

### 8.1 通用操作约定（每一步都遵守）

1. 执行前确认急停可用、人员离开运动包络；
2. 软件算出坐标后，填写《坐标记录表》：步骤名、WORLD、PLC XYZ、时间、操作者；
3. 甲方到位后，回报「已到位」或「无法到位（原因）」；
4. 我方再点「下一步」或重试本步；
5. 本步失败：**优先重试本步**，不轻易跳过（跳过需双方同意并记原因）。

### 8.2 首轮（建图轮）— 建议脚本

#### 步骤 F0：会前检查

- 运行模式：`完全真实 (field)`  
- 装载计划已加载  
- 日志目录可写  

#### 步骤 F1：设备连接检查（对应实验室第 1 步 / 现场 DEVICE_CHECK）

| 项 | 内容 |
|----|------|
| 动作 | 软件执行设备检查 |
| 我方 | 看顶栏「外接设备」状态与日志 |
| 甲方 | 协助排查网线、IP、供电 |
| 期望 | PLC / 雷达 / 相机均为已连接 |
| 记录 | 截图 + 失败原因（如有） |

#### 步骤 F2：插孔感知出坐标（对齐实验室「相机插孔识别」）

| 项 | 内容 |
|----|------|
| 动作 | 相机对托盘实拍，识别左右插孔，输出 WORLD（及换算后的 PLC XYZ） |
| 我方 | 界面展示识别图、插孔坐标；弹窗列出坐标供核对（可改数值但不由我方擅自动臂） |
| 甲方 | 按坐标将相机/臂移到约定观察位或插孔上方观察位（**本阶段默认不插取**） |
| 期望 | 左右孔坐标稳定、左右不反、高度合理 |
| 记录 | 标注图路径、左右孔 WORLD/PLC、人工目视是否对准 |

#### 步骤 F3：雷达车板粗定位（对齐实验室「雷达四角」）

| 项 | 内容 |
|----|------|
| 动作 | 雷达采点云 → 现场算法输出粗角点 |
| 我方 | 界面显示 P1–P4（或约定点数）WORLD；保存 PCD |
| 甲方 | 确认车头方向、车厢是否在雷达视野内 |
| 期望 | 粗点落在车板附近，顺序/命名与约定一致 |
| 记录 | 角点表 + 点云文件名 |

> F2 与 F3 在软件中可能并行；测试记录仍可按上表分列。

#### 步骤 F4：角点精定位与 WORLD（对齐实验室「相机精定位」）

| 项 | 内容 |
|----|------|
| 动作 | 按现场流程：雷达粗点 → 规划拍照位 →（甲方依坐标把相机送到车尾/车头拍照位）→ RGB-D → 角点识别 → WORLD |
| 我方 | 给出每一站 PLC/WORLD 目标；审核角点（若开启人工审核则当场确认）；输出最终 WORLD 角点 |
| 甲方 | 按站位坐标移动并保持稳定，供拍摄 |
| 期望 | 最终角点可用于划格；与卷尺/已知车厢尺寸量级一致 |
| 记录 | 每站位姿、角点像素与 WORLD、审核是否改点 |

#### 步骤 F5：划格 / 空间规划（对齐实验室划 B 区）

| 项 | 内容 |
|----|------|
| 动作 | 由最终相机 WORLD 角点判断板型并生成装载区域 |
| 我方 | 展示区域编号、中心点、四角 |
| 甲方 | 确认列/排方向、第一放货区是否符合工艺 |
| 期望 | 区域不越出车板；顺序符合 B1→B2…（或甲方指定） |
| 记录 | 区域表截图 |

#### 步骤 F6：目标区确认与「放置」（对齐实验室「等待人工放置」）

| 项 | 内容 |
|----|------|
| 动作 | 软件给出当前目标区域中心/放置相关坐标 |
| 我方 | 只发布坐标与区域 ID |
| 甲方 | 机械放置或人工放置托盘货到该区；放置完成后告知我方 |
| 期望 | 货在目标区内，可进行下一步回拍 |
| 记录 | 区域 ID、放置方式（机械/人工）、时间 |

#### 步骤 F7：放置后回拍校验（对齐实验室「到区中心实拍判区」）

| 项 | 内容 |
|----|------|
| 动作 | 软件给出回拍位坐标 → 甲方到位 → 实拍 → 判区/偏差输出 |
| 我方 | 记录判定结果、偏差、图像 |
| 甲方 | 确认判定是否与目视一致 |
| 期望 | 判区正确或偏差可解释；数据入库/落盘成功 |
| 记录 | 判定结论、偏差数值、照片路径 |

### 8.3 循环轮（第 2 轮及以后）— 建议脚本

对齐实验室循环：

1. **返回/去下一起点坐标**（我方给 XY，Z/R 按约定由现场保持）；  
2. **再次插孔识别出坐标**（默认仍不插取）；  
3. **上一区监测 / 当前区目标坐标**；  
4. **甲方放置**；  
5. **回拍判区**。

重复直到完成约定的 N 次或计划队列结束。

### 8.4 与软件完整 field 步骤的对照（便于内部同事）

| 测试脚本步骤 | 软件 field 步骤（参考） | 现场测试时机械臂 |
|--------------|-------------------------|------------------|
| F1 | 1 DEVICE_CHECK | 不动 |
| F2 | 2 / 3.1 相关感知 | 仅按需移到观察位 |
| F3 | 3.2 雷达 | 不动 |
| F4 | 4～7 粗点→拍照→识别→WORLD | 按站位坐标由甲方移动 |
| F5 | 8.1 规划 | 不动 |
| F6 | 8.2～9 中与目标/放置相关的坐标发布 | 甲方执行或人工放置 |
| F7 | 10.x 放后检测 | 甲方移到回拍位 |
| 循环 | 11～12 及下一轮 2/3/8/9/10 | 同上 |

> 若某次联调只做「感知 + 划格」、不做放置，可在会前砍掉 F6/F7，但须在纪要中写明范围缩小。

## 9. 坐标与接口约定（测试时必须写死）

### 9.1 推荐默认（与当前工程注释一致，若现场不同以书面为准）

- 坐标系：`world`  
- 单位：`mm`  
- 轴：X 右，Y 车辆前进，Z 上  
- 姿态角：按双方约定（常见仅关心 PLC 的 R；测试阶段可「现场保持 R」）  

### 9.2 每条坐标记录应包含

1. 步骤名称 / 轮次 / 区域 ID  
2. WORLD：`x_mm, y_mm, z_mm`（及 yaw 如有）  
3. PLC：`X, Y, Z`（R 是否下发单独标注）  
4. 是否允许自动写轴：是 / 否  
5. 甲方执行结果：到位 / 拒绝 / 改点后到位  
6. 备注（遮挡、光照、货偏等）  

### 9.3 下发策略（本阶段建议）

| 策略 | 说明 |
|------|------|
| 推荐 | 软件算出坐标 → 弹窗展示 → **甲方操作员确认后**再写轴或在甲方界面输入 |
| 不推荐（本阶段） | 我方无人值守自动连续写轴完成插取放货 |
| 禁止 | 在标定未确认、轴方向未核前开启高风险自动运动 |

## 10. 通过标准（建议稿，可改阈值）

### 10.1 连通性

- 连续 3 次启动，设备检查均能正确反映真实连接状态（含故意断线能报未连接）。

### 10.2 感知

- 插孔：在约定距离/高度下，左右孔识别成功率 ≥ 约定值（建议 ≥ 90%，样本 ≥ 10）；  
- 车板角点：首轮最终 WORLD 角点经甲方目视/卷尺复核，单点平面误差 ≤ 约定值（建议先记实测，再定考核阈值）；  
- 划格：区域全部落在车板内，顺序正确。

### 10.3 坐标闭环

- 甲方按坐标到位后，回拍/目视偏差在约定阈值内；  
- 同一静态场景重复 3 次，坐标抖动 ≤ 约定值。

### 10.4 流程稳定性

- 完整首轮 + N 次循环无 P0 级软件崩溃；  
- 关键步骤可重试恢复。

### 10.5 问题分级

| 级别 | 定义 | 处理 |
|------|------|------|
| P0 | 无法继续测 / 安全风险 / 坐标反号导致撞车风险 | 立即停测，当日必须有结论 |
| P1 | 主流程可走但关键结果错误 | 当日记录，给出临时规避或次日补测 |
| P2 | 体验/日志/显示问题 | 列入整改，不阻塞签字 |

## 11. 风险与应对

| 风险 | 表现 | 应对 |
|------|------|------|
| 标定未完成或不匹配 | 坐标整体偏移/旋转 | 只做连通与数据采集，不做运动闭环；催 C1–C4 |
| 轴方向与文档不一致 | 越走越偏 | 先做小行程点动核轴，再继续 |
| 现场光照差 | 角点/插孔不稳定 | 补光或改时段；记录环境 |
| 货/车与训练分布差异大 | 识别失败 | 采集失败样本，不硬跳过 |
| 网络不稳定 | 设备假在线/超时 | 固定 IP、独立网段、关多余防火墙 |
| 权限不清谁按急停 | 安全事故风险 | 明确唯一操作员与指挥口令 |
